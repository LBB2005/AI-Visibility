# Extractor gold set

Human labels used to validate the brand extractor, and the report generated from them.

| File | What it is |
|---|---|
| `extractor-gold.jsonl` | One labeled answer per line, with the full answer text embedded so the set is reproducible without the local database. |
| `validation.md` | Generated by `npm run gold:validate`. Do not edit by hand. |

## Labeling

```bash
npm run dev          # then open /label
```

Each card shows one answer as plain, unhighlighted text. The extraction model's output is
withheld by the server until a label is submitted, so the judgement can't be anchored by it.
Answer "does this name the brand?", optionally list every brand you see in order, then submit —
the model's answer is revealed afterwards for comparison.

## Scoring

```bash
npm run gold:validate
```

Reports Cohen's kappa on the binary decision for two deciders — the extraction model alone, and
the full pipeline including the raw-text fallback, which is what the app reports — plus raw
agreement, PABAK, prevalence, and micro-averaged precision/recall/F1 on the brand sets. The gold
set skews toward answers that do name a major brand, so kappa is always read next to raw agreement.

`lib/gold.test.ts` replays the set on every `npm test` and fails if agreement drops below the
thresholds set there. Lower a threshold only in a commit that explains why. With no gold set
present, that block skips and the suite still passes.
